# ai-jail v0.1.0

First stable release. Out of beta — installs cleanly on macOS and Linux,
all three preinstalled CLIs (Claude Code, OpenAI Codex, GitHub Copilot
CLI) authenticate once and stay logged in across sessions, and the
prompt now tells you which project a given terminal is jailed into.

## What ai-jail is

A Docker-based sandbox for running agentic coding CLIs against one
project folder at a time, without giving them your whole laptop.

- **Per-project bind mount.** The agent only ever sees the folder you
  pointed it at — not `$HOME`, not your SSH keys, not other projects.
- **Credentials in named Docker volumes.** Logins persist across
  sessions but never touch your host filesystem.
- **UID-matched non-root user.** Files the agent writes are owned by
  *you* on the host — no `sudo chown` dance.
- **Three CLIs preinstalled** via `pnpm` + `gh` extension: `claude`,
  `codex`, `gh copilot`.
- **Professional shell** — zsh, starship prompt, tmux, ripgrep, fd,
  git, gh.

## Highlights since v0.1.0-beta

### Cross-platform install actually works

The beta image build failed on macOS in two places. Both are fixed:

- `type -p curl` was assuming bash; Debian's `/bin/sh` is dash, which
  treats `-p` as an unknown command and exits 127. Replaced with POSIX
  `command -v curl`.
- The user/group setup tried to set `agent`'s GID to the host's GID,
  which collides on macOS where the host GID is 20 (already taken inside
  the base image by `dialout`). Now detects a pre-existing GID/UID and
  renames whichever group/user owns it to `agent`.

### Credentials persist across runs

The beta logged you out of every CLI between sessions. Three layered
bugs were stacked behind that single symptom:

- **Volume names were silently prefixed.** docker-compose was naming
  volumes `compose_ai-jail-claude` etc., while `scripts/ai-jail.sh`
  expected the unprefixed names. `ai-jail reset-auth` and `ai-jail
  prune` were no-ops. Now every volume is pinned with an explicit
  `name:`.
- **Named-volume mount points were root-owned.** `~/.claude`, `~/.codex`,
  and `~/.config/gh` weren't pre-created in the image, so Docker
  initialized them as `root:root` and the in-container `agent` user
  couldn't write its config. The Dockerfile now pre-creates every mount
  point owned by `agent`.
- **No Secret Service for libsecret.** Claude Code on Linux uses
  libsecret to persist OAuth tokens — but the image had no DBus session
  bus or keyring daemon, so login was effectively in-memory. The image
  now ships `libsecret-1-0`, `libsecret-tools`, `gnome-keyring`, and
  `dbus-x11`; the entrypoint starts a session bus + auto-unlocks the
  keyring; a new `ai-jail-keyrings` volume persists the keyring file.
- **`~/.claude.json` was outside any volume.** Claude's user config
  lives at the home root (sibling of `~/.claude/`), not inside the
  credential dir. Every fresh container saw a missing config and
  re-ran onboarding. The entrypoint now symlinks
  `~/.claude.json` → `~/.claude/.claude.json` so it lands inside the
  persisted volume.

Same fix that helped Claude Code also covers GitHub Copilot CLI,
which is keyring-backed too.

### Prompt tells you which jail you're in

Working with multiple ai-jail terminals at once was confusing because
every prompt looked the same — `/workspace` is the in-container path,
identical no matter which host project is mounted. The prompt now
surfaces three signals:

```
AI-JAIL · my-project workspace on  main  14:23
```

- **Project name.** Derived from the workspace path's basename and
  passed in as `AI_JAIL_PROJECT`.
- **Git branch.** Renders automatically when `/workspace` is a git
  repo (no GitHub remote required — any git repo).
- **Local time.** Container time now matches the host's timezone
  (passed through via `$TZ`) instead of UTC.

### `claude` and `codex` actually work out of the box

The beta build hit two binary-installation bugs that left both CLIs
failing on first launch with cryptic errors:

- pnpm 10 blocks dependency lifecycle scripts by default, so the
  Claude Code postinstall (which downloads the platform-native binary)
  was silently skipped. The Dockerfile now invokes the postinstall
  explicitly after `pnpm add -g`.
- The `ai-jail-pnpm-store` volume was mounted at `$PNPM_HOME`, which
  shadowed the global bin shims at runtime. Narrowed to
  `$PNPM_HOME/store` so caching still works without hiding the CLIs.

## Install

```sh
git clone https://github.com/yuryalencar/ai-jail.git
cd ai-jail
./scripts/install.sh
exec $SHELL -l
```

See [README](../../README.md#install) for the full flow.

## Daily use

```sh
ai-jail ~/code/my-project          # interactive zsh in the jail
ai-jail ~/code/my-project claude   # run claude non-interactively
ai-jail                             # uses $PWD
```

## Known limitations (still v0.1)

- **Open network egress.** Anything inside the container can reach the
  public internet. Allowlisting is on the v0.2 roadmap.
- **Standard Docker isolation only.** No seccomp, AppArmor, or gVisor
  profile. Codex emits a `bubblewrap not found` warning at startup —
  this is intentional for v0.1 (Docker is the primary sandbox; bwrap
  would be defense-in-depth on top).
- **Per-machine image build.** The image bakes in your host UID/GID, so
  every developer rebuilds locally on first install. See
  [docs/uid-gid.md](../uid-gid.md) for why.
- **No Python / Go / Rust toolchains.** Node-only base. A
  `Dockerfile.full` variant is on the roadmap.

## Upgrading from v0.1.0-beta

If you installed the beta, your old credential volumes are
prefixed (`compose_ai-jail-*`) and unrecoverable for Claude Code.
After pulling and rebuilding:

```sh
git pull
ai-jail build
ai-jail prune          # one-time: drops the beta's volumes
```

Then `ai-jail <path>` and re-`/login` once per CLI. New logins persist.
