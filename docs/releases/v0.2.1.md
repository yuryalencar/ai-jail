# ai-jail v0.2.1

First release after v0.1.0. Adds the Go toolchain, makes `ai-jail update`
actually keep claude/codex on the latest published versions, and ships
a real `--help` for the shell function. The most-felt practical fix:
`claude` and `codex` no longer break when pnpm rolls a new major.

## Highlights

### Go toolchain in the image

`go` is now baked into the image alongside Node.js. Module cache and
installed binaries persist across sessions in a new `ai-jail-go` named
volume mounted at `~/go`. No setup per project — `go mod init`,
`go get`, `go build`, `go test` all work the same as on the host but
scoped to the bind-mounted project folder.

| Toolchain | Version |
|---|---|
| Node.js | 22 (npm 10, pnpm 11) |
| Go | 1.26 |
| Python | 3.11 (no pip / venv preconfigured — install per project) |

### `ai-jail update` actually updates the CLIs

In v0.1.0, `ai-jail update` re-pulled the base image and rebuilt — but
Docker's layer cache kept the `pnpm add -g` step pinned to whatever was
resolved last time, so claude-code and codex versions silently froze.
Now `ai-jail update` passes a `CLI_REFRESH` build arg with a timestamp,
invalidating just the install layer and forcing `pnpm` to re-resolve
`@latest` from npm. Day-to-day `ai-jail build` stays cache-friendly.

```sh
ai-jail update      # rebuild + pull latest claude/codex from npm
ai-jail build       # fast rebuild, keeps current CLI version
```

### `ai-jail --help` and `ai-jail init [path]`

- New `ai-jail help` / `-h` / `--help` prints usage, subcommands,
  examples, and a docs pointer in one screenful.
- `ai-jail init` now accepts an optional path:
  `ai-jail init my-project` works without `cd`'ing first, and prints
  the absolute destination so misroutes are obvious.

### Prompt shows project name, branch, and local time

The starship prompt now identifies which project a given terminal is
jailed into:

```
AI-JAIL · my-project workspace on  main  14:23
```

Project name comes from the workspace path's basename. Git branch
renders automatically when `/workspace` is a git repo. Container time
matches the host's timezone (passed through via `$TZ`) instead of UTC.

## Bug fixes since v0.1.0

- **pnpm 11 broke claude/codex.** `corepack prepare pnpm@latest` pulled
  pnpm from 10 to 11. The new global layout made our old postinstall
  lookup silently miss `install.cjs`, and the now-removed
  `ai-jail-pnpm-store` volume started shadowing the *actual* package
  content (not just the cache). See
  [docs/bugs-solved/pnpm-11-broke-claude-and-codex.md](../bugs-solved/pnpm-11-broke-claude-and-codex.md).
- **`ai-jail prune` was missing volumes.** The list got out of sync
  with compose. Now matches exactly.
- **Subcommand dispatcher confusion on `init`.**
  `ai-jail my-project init` used to silently try to `exec init` inside
  the container. The dispatcher behavior didn't change (still
  `<path> <cmd-in-container>`), but `init` now accepts its own path
  arg as the natural fix.

## Install

```sh
git clone https://github.com/yuryalencar/ai-jail.git
cd ai-jail
./scripts/install.sh
exec $SHELL -l
```

## Upgrading from v0.1.0

```sh
cd ~/.ai-jail            # or wherever you cloned
git pull
ai-jail build            # rebuilds with the new Dockerfile (Go, pnpm-11 fix, refresh ARG)
docker volume rm ai-jail-pnpm-store    # one-time: drop the orphan volume from v0.1
ai-jail <path>
claude                   # works on the new pnpm layout
```

Credentials in `ai-jail-claude`, `ai-jail-codex`, `ai-jail-gh`,
`ai-jail-keyrings` carry over — no re-login needed.

## Known limitations (still v0.x)

- **Open network egress.** Allowlisting is on the roadmap.
- **Standard Docker isolation only.** No seccomp / AppArmor / gVisor
  profile. Codex still emits a `bubblewrap not found` warning at
  startup — defense-in-depth on top of Docker, not required.
- **Per-machine image build.** The image bakes in your host UID/GID;
  every developer rebuilds locally on first install. See
  [docs/uid-gid.md](../uid-gid.md).
- **No Rust toolchain.** Roadmap item.
